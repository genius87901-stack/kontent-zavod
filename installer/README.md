# Слой упаковки в самораспаковывающийся установщик (`installer/`) — OWNER

Этот каталог превращает клиентскую коробку в **ОДИН самораспаковывающийся `.exe`**,
который на **чистой Windows-машине БЕЗ интернета и без GPU** разворачивает завод и
рендерит ролик. Владелец — ветка OWNER (слой установки, CONTRACT.md §5). Движок
(`engine_*`, `talk_*`, `render_reels`, `checks`) отсюда **не трогается** — упаковка,
не переписывание.

## Выбранный формат (обоснование одной строкой)

> **Inno Setup 6** — один подписываемый `.exe` (LZMA2 + Pascal-постскрипт) тянет
> офлайн-разворачивание многогигабайтной нагрузки с embeddable-Python и
> пост-установочным скриптом (venv/модели/дым-рендер) надёжнее 7-Zip SFX (нет
> логики шагов) и удобнее NSIS для больших payload'ов и человеческого мастера.

Альтернативы отклонены кратко: **7-Zip SFX** — нет пост-скрипта/UI/лицензии/деинсталла;
**NSIS** — мощнее, но скриптовый язык и работа с многогигабайтными файлами болезненнее,
а нам нужен just-works мастер на русском.

## Что тут лежит

| Файл | Роль | Где исполняется |
|---|---|---|
| `kontent-zavod.iss` | Спека Inno Setup: из стейджинга собирает `.exe`, пост-скриптом разворачивает окружение | **компилируется на Windows** (`iscc.exe`) |
| `activation.py` | **OTP-активация, фаза 1 реализована (BOX-29):** офлайн-проверка подписи лицензии (Ed25519) + отпечаток машины + локальная запись + гейт `require_activation()`. Обратно совместим с legacy-кодом `KZ-XXXXX-…`. См. `docs/ДИЗАЙН_OTP_ВЕРИФИКАЦИИ.md` | клиент (шаг 0 мастера `/install`) |
| `_ed25519.py` | Вендоренный чистый-python Ed25519 (подпись/проверка), stdlib-only — без нативных колёс, Nuitka-дружелюбно. Совпадает с RFC 8032 | в коробке (импорт activation) |
| `machine_fingerprint.py` | Отпечаток машины (SHA-256 от MachineGuid+серийник тома / IOPlatformUUID / machine-id), без ПДн | в коробке (импорт activation) |
| `license_pubkey.py` | **ПУБЛИЧНЫЙ** ключ Ed25519 владельца (генерит `license_gen.py --init`). В git и в коробке | в коробке (импорт activation) |
| `license_gen.py` ⛔ | **OWNER-ONLY, НЕ в git/коробке:** генерит пару ключей, выпускает подписанные бессрочные лицензии `seats=2`. Приватное семя — в `installer/.owner_keys/` (вне git) | только машина владельца |
| `offline_install.py` | Офлайн-развёртывание `.venv` из wheelhouse; закрепляет офлайн-режим pip | клиент (пост-скрипт `.exe`) |
| `smoke_render.py` | Дымовой офлайн-рендер (Pillow+шрифт+ffmpeg → `.mp4`) — доказывает, что рендер жив | клиент/приёмка |
| `fetch_wheels.py` | Вендоринг win-колёс в `installer/vendor/wheels` + лицензионный гейт. **Фикс 03.08:** пин `omegaconf==2.3.0` (обход зацикливания pip≥24.1) + сборка `antlr4-python3-runtime==4.9.3` wheel из sdist | подготовка (владелец, онлайн) |
| `license_audit.py` | Механизированный GPL/AGPL-стоп по РЕАЛЬНЫМ файлам лицензий | подготовка/CI |
| `preflight.py` | Приёмка коробки ДО сборки: состав payload, 0 секретов, полнота манифеста, лицензии, наличие всех win-колёс | подготовка (мак/Windows) |
| `build_windows.ps1` | **Одна команда**: колёса → гейт → веса → стейджинг → preflight → `iscc` → `.exe` | **Windows-машина сборки** |
| `build_manifest.py` → `manifest.json` | Манифест версий компонентов офлайн-коробки | подготовка |

## Как это собирается (кратко; полный чек-лист — `BUILD-RECIPE.md`)

```
[mac/подготовка]                         [Windows-машина Валерии]
build_box.py --stage-sfx stage/   ─┐
fetch_wheels.py  (онлайн, 1 раз)   ─┼──►  iscc kontent-zavod.iss  ──►  КонтентЗавод-Установщик.exe
install_models.py (онлайн, 1 раз)  ─┘         (offline_install.py пост-скриптом)
```

Полностью офлайн у клиента: интерпретатор (embeddable-Python), зависимости
(вендоренные колёса), веса моделей (`.cache_models`), шрифты, музыка — всё внутри.
Из сети при установке НЕ качается **ничего, кроме музыки** (отдельный необязательный
шаг мастера, переживает отсутствие интернета).

## Офлайн-гарантия без правки движка

`offline_install.py` кладёт в `.venv/pip.ini` строки `no-index=true` +
`find-links=<wheelhouse>`. Поэтому даже штатные шаги мастера `/install` (который мы
**не переписываем**, а упаковываем) идут офлайн и идемпотентно: уже поставленное не
тянется из сети. Так офлайн держится без единой правки `make_venv.py`/движка.

## Лицензии

Полный разбор — `THIRD_PARTY.md`. Гейт `license_audit.py` **останавливает** сборку
при GPL/AGPL в цепочке. Статус блокеров:

- `pillow_heif` → **закрыт**: владелец intake перешёл на `pi-heif` (LGPLv3, декодер-only);
- `av==15.1.0` → **отложен владельцем (BOX-27, был BOX-23)**: проверено **windows**-колесо —
  внутри `av.libs/` лежат `libx264` (GPL-2.0+) и `libx265` (GPLv2), и `avcodec` с ними
  слинкован. Заявленная лицензия пакета (`BSD-3-Clause`) описывает только обвязку. Проект
  `av` не импортируется ни разу (0 использований) — риск берётся «прицепом». Гейт
  **останавливает** сборку; владелец 02.08 решил вернуться через пару дней. Разбор с
  доказательствами и путями решения — `THIRD_PARTY.md`. Владелец — **engine-media**.
  **GPL — не блокер запуска** (осознанно отложено): для приёмочной сборки используется
  `--skip-audit`, пока решение не принято.
