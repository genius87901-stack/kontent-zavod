# /niche-hooks — разведка ниши до смыслов

Отдельный ручной слой конкурентной разведки. Он **не встроен** в авто-пайплайн
генерации каруселей и Reels и **не должен** в него встраиваться. Человек
запускает его сам под конкретного клиента/нишу, читает результат глазами и
только потом скармливает движку.

**Ценность — не в отчёте с цифрами, а в готовом сырье для распаковки смыслов.**
Сырые метрики без слоя смыслов бесполезны. На выходе — markdown-файл, разделы
которого ложатся прямо в структуру смыслов проекта (`CONTENT_BIBLE_*.md`:
разделы «50 ХУКОВ ДЛЯ REELS», «ШАБЛОННЫЕ ХУКИ», материал под «100 ТЕМ» и боли).

## Три слоя (это и есть весь смысл скилла)

1. **МЕТРИКИ** — находим в нише ролики, кратно перебившие среднее по своему
   аккаунту (аутлаеры). Источник цифр — vidIQ MCP.
2. **РАЗБОР** — по найденным аутлаерам смотрим первые секунды: хук, первый
   кадр, текст на экране, темп, лицо. Источник — vidIQ (Instagram) или скилл
   `/watch` (YouTube/TikTok).
3. **СМЫСЛЫ** — сводим в банк хуков и паттернов, привязанный к цифрам. Это и
   есть продукт.

## 🔴 ПЕРЕД ЛЮБЫМ ПРОГОНОМ — деньги и правда

- **Шаг 0 — есть ли вообще коннектор vidIQ.** Инструменты `vidiq_*` появляются
  только если человек подключил коннектор vidIQ в самом Claude. Если их нет
  (вызов недоступен или падает с ошибкой доступа) — **не показывай техническую
  ошибку и не пытайся обойти**. Скажи прямо: «Разведка конкурентов работает
  через сервис vidIQ, он у вас пока не подключён к Claude» — и проведи по
  шагам из «ПОДКЛЮЧЕНИЕ_VIDIQ.md» (лежит в корне завода). Главное, что важно
  донести: регистрация на сайте vidiq.com и подключение коннектора в Claude —
  это два РАЗНЫХ действия, одного входа на сайт недостаточно. После подключения
  предложи повторить запрос — ничего заново настраивать не нужно.
- **Сначала всегда `vidiq_balance`.** Покажи человеку остаток кредитов и смету
  прогона до запуска. Не запускай сборы вслепую.
- **Порог 50 кредитов.** Любой прогон дороже 50 кредитов — только после явного
  «да» человека с выбранной глубиной. Цены: `vidiq_balance` — 0;
  `vidiq_instagram_tiktok_outlier_search` — 5; `vidiq_ig_profile_reels` — 5;
  `vidiq_outliers` — 5; **`vidiq_watch_shortform_content` — 10** (дорогая часть,
  умножается на число разбираемых роликов).
- **Смета по глубине разбора (Instagram):** сбор 5 + N×10 за разбор.
  Топ-12 ≈ 125 кр · топ-6 ≈ 65 кр · топ-4 ≈ 45 кр (влезает под порог). Предложи
  человеку глубину, а не решай за него.
- **НЕ придумывай метрики.** Если vidIQ не отдал цифру — так и пиши: «данных
  нет». Выдуманный breakout-score хуже отсутствия данных. Наблюдение из разбора
  подавай как наблюдение, а не как измеренный факт.
- `vidiq_watch_shortform_content` возвращает кредиты сам, если разбор упал —
  риск слить бюджет на ошибке низкий, но смету всё равно показывай заранее.

## Вход

Спроси у человека, если не задано:

- **Ниша словами** — обязательна. Пример: «точки роста бизнеса, экспертный
  контент для предпринимателей».
- **Платформа** — `instagram` (по умолчанию) · `tiktok` · `youtube`.
- **Аккаунты конкурентов** — опционально, список хендлов. Если даны — добираем
  их рилсы адресно.
- **Регион / аудитория** — для рескоринга и языка (например Россия, ru).

## Алгоритм

### Слой 1 — собрать 15–25 аутлаеров

**Instagram / TikTok:**
```
vidiq_instagram_tiktok_outlier_search(
  query = <ниша словами>,
  audienceQuery = "Culture/Region: Russia/Russian; Global: false; Demographics: <кто аудитория ниши>;",
  resultsPerPlatform = 20,      # 1 вызов = 5 кр, отдаёт секции IG и TikTok
  descriptionLanguage = ["ru"], # при необходимости
  viewsMin = 10000
)
```
- `audienceQuery` строго в формате `Culture/Region: ...; Global: <true|false>; Demographics: ...;`.
- Секции IG и TikTok несравнимы по скору — не смешивай их в один рейтинг.
- Если человек дал аккаунты — по каждому дополнительно
  `vidiq_ig_profile_reels(handle=...)` (5 кр/аккаунт): отдаёт до 12 рилсов с
  play/like/comment и обложкой. URL рилса собираешь из shortcode:
  `https://www.instagram.com/reel/<shortcode>/`.

**YouTube:**
```
vidiq_outliers(
  keyword = <ниша>, language = "ru",
  minOutlierScore = <разумный порог>, contentType = "short",
  limit = 25, publishedWithin = "threeMonths"
)
```

### Слой 2 — отфильтровать до топ-12

- Отбрось всё, где высокие просмотры объясняются просто размером аккаунта.
  Нужны ролики с **аномальным отношением просмотров к базе** (аккаунта/медианы),
  а не абсолютные хиты больших блогеров.
- Отсортируй по этому отношению (breakout / outlierScore / views÷followers —
  тем, что реально отдал vidIQ). Возьми **топ-12** (или меньше — по согласованной
  глубине/бюджету).
- Если vidIQ не дал базы для нормировки по какому-то ролику — не выдумывай
  коэффициент, пометь «нормировка недоступна» и суди по тому, что есть.

### Слой 2.5 — 🔴 ПОКАЗАТЬ СПИСОК КОНКУРЕНТОВ И ДОЖДАТЬСЯ ОДОБРЕНИЯ (обязательно)

**Слои 1–2 — дешёвые (поиск аутлаеров ~5 кр). Слой 3 — дорогой (разбор ~10 кр за
ролик). Поэтому МЕЖДУ ними — стоп: сам разбор НЕ запускать, пока человек не
одобрит список.**

1. Собери из топ-12 **предлагаемый список к анализу**: по каждому — хендл,
   площадка, просмотры/выброс, ниша, одна строка «почему в списке».
2. Покажи его человеку таблицей вместе со **сметой Слоя 3** (кол-во роликов ×
   10 кр = итог; текущий остаток из `vidiq_balance`).
3. Спроси через `AskUserQuestion`: **запускать разбор этого списка / убрать
   кого-то / добавить своих конкурентов / отменить.** Дай выбор, не запускай
   вслепую.
4. **Только после явного «да»** переходи к Слою 3. Если человек правит список —
   пересобери и покажи снова. Отмена — останавливайся, дорогие вызовы не делаешь.

### Слой 3 — разобрать первые 8 секунд каждого из ОДОБРЕННОГО списка

Достать по каждому: **текст первой фразы**, **что в первом кадре**, **текст на
экране**, **темп смены планов**, **есть ли лицо в кадре**.

- **Instagram** — НЕ используй `/watch` (yt-dlp по IG нестабилен без кук).
  Бери `vidiq_watch_shortform_content(url = <полный URL рилса>)` — 10 кр,
  асинхронно: вернёт `mcpJobId`, опрашивай `vidiq_job_poll` до `completed`.
- **YouTube / TikTok** — скилл `/watch` (бесплатно, если есть субтитры):
  ```bash
  SKILL_DIR="$HOME/.claude/plugins/marketplaces/claude-video/skills/watch"
  python3 "$SKILL_DIR/scripts/watch.py" "<URL>" \
    --detail efficient --start 0 --end 8 --out-dir <scratchpad>/nh_watch
  ```
  Затем `Read` каждый кадр из отчёта, чтобы увидеть первый кадр и текст на
  экране. Без ключа Groq (`~/.config/watch/.env`) TikTok без субтитров даст
  только кадры — добавь `--no-whisper`, транскрипт возьми из кадров/подписи и
  пометь, что речь не расшифрована.

## Выход — формат (ШАГ 4)

Один markdown-файл, читаемый человеком. **Не машинный дамп, не таблица цифр.**
Разделы совпадают со структурой смыслов проекта, чтобы результат писался В неё:

Сохранять в `research/niche-hooks/<ниша-slug>_<ГГГГ-ММ-ДД>.md` (путь
относительно корня репозитория). Шапка файла: ниша, платформа, регион, дата,
**сколько кредитов потрачено**, сколько аутлаеров найдено/разобрано.

Разделы:

1. **БАНК ХУКОВ** — до 12 первых фраз **дословно**, у каждой в скобках стоящая
   за ней метрика (просмотры / breakout / отношение к базе — что отдал vidIQ) и
   ссылка. → ложится в «50 ХУКОВ ДЛЯ REELS» Content Bible.
2. **ПОВТОРЯЮЩИЕСЯ СТРУКТУРЫ** — какие типы открытия встретились больше одного
   раза, сколько раз, с какими цифрами. Меньше двух примеров — это не паттерн, а
   единичный случай, так и помечай. → «ШАБЛОННЫЕ ХУКИ».
3. **ВИЗУАЛЬНЫЕ ПАТТЕРНЫ** — что в первом кадре у выстреливших, что общего
   (лицо/текст/локация/темп).
4. **ТЕМЫ С ОТКЛИКОМ** — о чём эти ролики, сгруппировать по смыслу. → материал
   под «100 ТЕМ» и боли аудитории.
5. **ЧЕГО НЕТ В НИШЕ** — темы и форматы, которых в выборке не оказалось. Это
   гипотезы на пустоту, помечай как гипотезы, а не как факт.
6. **СЫРЬЁ** — полный список: URL + все метрики, что отдал vidIQ, чтобы человек
   мог перепроверить. Здесь честно «данных нет», где их нет.

После сохранения покажи человеку: потрачено кредитов, найдено аутлаеров, и
готовый файл целиком.

## ШАГ 5 — ПЕРЕДАЧА В ГЕНЕРАЦИЮ ХУКОВ И СЦЕНАРИЕВ (со смыслами клиента)

Разбор конкурентов — сырьё, а не продукт. Сразу после файла разведки передай его
в генерацию, **скрестив с библиотекой смыслов клиента**, чтобы новые хуки/сценарии
были и «в голосе бренда», и с учётом того, что реально залетает в нише:

1. **Прочитай `CONTENT_BIBLE_*.md` клиента** (ниша, аудитория, боли, голос бренда,
   продукт, кодовые слова). Без него — только чужие формы без смысла.
2. **Скрести источники:** банк хуков + повторяющиеся структуры + темы-с-откликом
   из разведки × боли/темы/продукт клиента из Content Bible.
3. **Сгенерируй под клиента:**
   - **хуки** (`/hook`) — по 3–4 варианта на тему, в голосе бренда, по паттернам
     конкурентов, но про смыслы клиента (не копия чужих);
   - **сценарии Reels** (`/reels`, `script_writer`) — открытие от кульминации,
     формат-победитель ниши (обычно говорящая голова + скринкаст), CTA с кодовым
     словом клиента.
4. **Правило:** не копировать чужие ролики дословно; брать ФОРМУ (структура хука,
   темп, формат) и наполнять СМЫСЛОМ клиента из Content Bible. Запрещённые слова
   клиента (напр. «печётся») — не использовать.
5. Итог отдать человеку на выбор: разведка → хуки → сценарии одной цепочкой.

## Границы (соблюдать строго)

- **Ручной запуск.** Не встраивай вызов в авто-пайплайн генерации.
- **Не трогай** рендер-движок (Pillow/opencv/mediapipe/ffmpeg), автопостинг и
  предохранители публикации. Этот скилл их не касается.
- **Не пиши Python**, где логика умещается в этот промпт. Скрипты — только если
  физически без них нельзя.
- **Инструмент входит в клиентскую коробку** (этап 3 установки) и помечен
  `ships_to_client: true`. Это **ручной** инструмент: тратит платные кредиты vidIQ,
  в авто-пайплайн не встраивается.
- **vidIQ — на аккаунте того, кто запускает.** У клиента это ЕГО личный vidIQ и ЕГО
  кредиты (отдельная платная регистрация, наши ключи в коробку не едут). Всегда сначала
  `vidiq_balance` и смета — деньги чужие, показывай их до запуска.
