Ты выполняешь задачу «Шапки профилей»: собираешь готовые, продающие описания профиля/канала/сообщества для каждой соцсети клиента — на основе его личной Книги смыслов. Результат должен быть готов вставить в профиль без правок.

Если пользователь передал аргумент: `$ARGUMENTS` — генерируй только для перечисленных площадок. Если аргумент пуст — используй список площадок клиента (см. шаг 1) или Базовую таблицу ниже.

## Шаг 1. Найди источники — не придумывай, а ищи

1. Найди файл Книги смыслов клиента. Ищи по маскам: `*книга*смысл*.md`, `*book-of-meaning*`, `СМЫСЛЫ*.md`, в папках `docs/`, `книга/`, `client/`, корне проекта. Если не находишь — спроси у клиента путь к файлу, не придумывай содержимое.
2. Проверь, есть ли у клиента готовый список площадок (`config/platforms.*`, раздел «11. Площадки» внутри самой Книги смыслов). Если есть — используй именно его вместо Базовой таблицы.

## Шаг 2. Возьми из Книги смыслов только нужное

Из соответствующих разделов эталонной структуры (11 разделов):

- **Портрет клиента** + **Миссия и позиционирование** → кто он, для кого, чем отличается от других в нише
- **Смысловое ядро** → одна главная мысль / УТП, вокруг которой строится хук
- **Готовые хуки** → берёшь готовую зацепку для открывающей строки, не сочиняешь новую с нуля
- **Кейсы клиентов** → один короткий обезличенный результат с цифрой, релевантный площадке
- **Призывы к действию** → готовый CTA, без отсебятины
- **Площадки** → если там уже прописаны конкретные ссылки/хэндлы — вставляй их как есть

**Жёсткое правило.** Если под конкретную площадку не хватает данных (нет подходящего кейса, нет цифры, непонятна ссылка) — не сочиняй. Пометь `[нет данных — уточнить у клиента: <что именно>]` и собери описание из того, что есть по факту.

## Шаг 3. Собери описание по формуле, сжимая под лимит площадки

Приоритет блоков (при нехватке места убирай с конца списка, а не обрезай хук):

1. **Хук** — первая строка/первые ~40–60 знаков, за которые площадка не обрезает превью
2. **Экспертность** — кто ты + почему тебе можно доверять (стаж, цифра, специализация)
3. **Кейс** — короткий результат клиента с цифрой (если влезает и есть в Книге смыслов)
4. **CTA** — призыв к действию
5. **Ссылка/хэндл** — если у площадки есть кликабельное поле под ссылку в био

## Шаг 5. Стилевые правила 2026 года

- Без переспама ключевыми словами — алгоритмы YouTube и Дзена в 2026-м палят искусственные вставки лучше, чем раньше; ключевая мысль должна звучать естественно внутри предложения
- Для площадок с поиском (YouTube, Дзен, LinkedIn) — ключевая фраза/УТП должна попасть в первые 40–100 знаков, не в конец
- Эмодзи — уместны как визуальные разделители в коротких bio (Instagram, TikTok, VK-статус); в LinkedIn — только если это соответствует голосу бренда клиента, по умолчанию без них
- Площадки с одной кликабельной ссылкой в био (Instagram, TikTok) — выноси только одну ссылку; если у клиента несколько (сайт + Telegram + запись), уточни, какую ставить первой, не выбирай сам
- Не копируй формулировки один в один между площадками — хук должен отличаться, даже если смысл один

## Шаг 6. Формат вывода

Сохрани результат в файл `output/шапки-профилей-<дата>.md` (либо туда, где клиент обычно ищет результаты завода). Структура:

```markdown
# <Имя клиента> — описания профилей (<дата>)

## Instagram — Bio (лимит 150, использовано NN)
<готовый текст>

## VK — личная страница, статус (лимит 140, использовано NN)
<готовый текст>

## VK — сообщество, описание (лимит ~4000, использовано NN)
<готовый текст>

## Telegram — личный профиль (лимит 70, использовано NN)
<готовый текст>

## YouTube — о канале (лимит 1000, использовано NN)
<готовый текст>

## TikTok — Bio (лимит 80, использовано NN)
<готовый текст>
```

Для каждой площадки — счётчик «использовано / лимит», чтобы клиент сразу видел, что текст точно влезет.

## Шаг 7. После генерации

В чате коротко отчитайся: какие площадки готовы, где стоят пометки `[нет данных]` и что именно нужно уточнить у клиента. Не заводи долгий диалог с уточняющими вопросами до генерации — сначала выдай максимально готовый результат на основе того, что есть в Книге смыслов, вопросы задавай только по реальным пробелам, уже после того как показал черновик.
