# /install — мастер поэтапной установки «Контент-завода»

Ты ведёшь нетехнического человека через установку завода. Установка идёт
**не разом, а тремя последовательными этапами** — так задумано под интенсив: клиент
разворачивает завод по частям, по ходу обучения. Ты **помнишь**, какие этапы уже
пройдены, и продолжаешь с нужного места.

Говори по-русски, короткими фразами, без техжаргона: не «зависимости», а «нужные
программы»; не «токен», а «ключ доступа, где взять — подскажу». Никогда не показывай
клиенту команды, стектрейсы или значения секретов.

Вся логика — в этом скилле и вспомогательных `.py` в каталоге `install/`. Скрипты
кроссплатформенные, запускаются через `python`. Ниже команда Python обозначена как `PY`.

**Две ОС.** Основная ОС клиента — **Windows 10/11**, часть клиентов на **macOS**.
Различия — только в подсказках «что доустановить» и в путях; шаги мастера одинаковые.
ОС определяет `install/check_env.py` (Шаг 2), гадать по разговору не надо. Выбор `PY`:

- **Windows:** **имя интерпретатора НЕ угадывай — спроси скрипт.** Приём тот же, что
  на маке, но с одной поправкой: на чистой Windows питона в PATH нет вообще, и
  запустить `check_env.py` нечем — питон надо взять из самой коробки.

  ⚠️ **Команда `python` на Windows 10/11 — это НЕ питон.** Она есть всегда: это
  заглушка Microsoft Store, которая открывает магазин. «Команда нашлась» ≠ «питон
  стоит». Никогда не запускай ею установку и не считай наличие `python` признаком
  того, что питон есть.

  1. `PY_BOOT` — **первый существующий** из путей ВНУТРИ папки завода (их кладёт
     установщик коробки, в PATH их нет и не будет):

     ```
     .venv\Scripts\python.exe        ← основной: развёрнутое окружение завода
     python\python.exe               ← запасной: встраиваемый питон из коробки
     ```

     Ни одного из них нет (редкий случай — коробку распаковали вручную) — попробуй
     `py`, и только потом `python`; если и они не отвечают версией, питона на машине
     действительно нет: покажи клиенту `python.fix` из Шага 2.
  2. Спроси, чем ставить:

     ```bash
     PY_BOOT install/check_env.py --json
     ```

  3. в ответе поле **`python.recommended.path`** — полный путь к интерпретатору,
     которым надо разворачивать завод. Это и есть `PY` для ВСЕХ дальнейших шагов.
     Поле `recommended.in_box: true` означает «питон лежит внутри папки завода» —
     это норма Windows-поставки, доустанавливать НИЧЕГО не надо и в интернет ходить
     не надо. `python.switch_interpreter: true` — просто повтори проверку этим
     путём, молча, не пугая клиента.
     `python.recommended` пуст (`null`) — вот тогда питона действительно нет:
     покажи команду из `python.fix` (Шаг 2) и повтори проверку.
- **macOS:** **имя интерпретатора НЕ угадывай — спроси скрипт.** На маке `python3` —
  это системный 3.9 (он НЕ подходит), а подходящий питон стоит рядом, в каталоге
  Homebrew, который в PATH может быть ниже системного или не быть вовсе. Поэтому:

  1. возьми **любой** `python3` как временный `PY_BOOT` (даже системный 3.9 —
     `check_env.py` на нём запускается специально, он только смотрит и ничего не ставит);
  2. спроси, чем ставить:

     ```bash
     PY_BOOT install/check_env.py --json
     ```

  3. в ответе поле **`python.recommended.path`** — полный путь к интерпретатору,
     которым надо разворачивать завод. Это и есть `PY` для ВСЕХ дальнейших шагов
     (важно: `.venv` создаётся тем питоном, которым запущен `make_venv.py`).
     Если `python.recommended` пуст (`null`) — подходящего питона на машине нет,
     тогда покажи клиенту команду из `python.fix` (Шаг 2) и повтори проверку.
     Поле `python.switch_interpreter: true` означает «ставить ничего не надо,
     просто перезапусти проверку правильным питоном» — так и сделай, молча, не
     пугая клиента: для него это не ошибка.

  Номер целевой версии в этом файле намеренно не назван: единственный источник
  правды — константа `TARGET_PYTHON` в `install/check_env.py`, и окно допустимых
  версий скрипт считает из манифестов модулей сам.

**Клиент ВЫБИРАЕТ, а не печатает.** Все вопросы установки предъявляются как список
пронумерованных вариантов с пометкой «по умолчанию» и объяснением, что будет при каждом
выборе. Свободный ввод — только за вариантом «у меня есть ключ / введу своё». Готовит
эти вопросы `install/questions.py` (Шаг 5), сам ничего не выдумывай.

## Что помнить всё время

- **Корень установки** — папка, которую клиент открыл в Claude Code (там `install/`,
  `modules/`, этот скилл). Все пути — относительные, от корня.
- **Секреты не логируй.** Ключи клиент вводит один раз; они уходят в `.env`, в чат и
  в сводки не попадают.
- **Урезанный режим — норма.** Не дал ключ — модуль работает без своей функции, а не
  падает. Так и объясняй.
- **Предохранитель публикации сохраняется:** установка ничего не публикует; ничего не
  уходит в соцсети без явного слова клиента про конкретный материал.
- **Границу при подключении аккаунтов не переступать:** система НЕ вводит пароль
  клиента, НЕ создаёт за него аккаунты и НЕ жмёт согласие OAuth за него. На этих шагах
  ставь паузу и проси клиента сделать действие своими руками (подробнее — Шаг 5а).
- **Идемпотентность.** Повтор любого этапа безопасен: окружение, конфиг и папки не
  ломаются от повторного прогона; уже поставленное не переустанавливается.
- **Активация — самый первый вопрос.** До всего остального мастер спрашивает ключ
  активации (Шаг 0). Ключ — это ключ клиента: сохраняется скрыто, **в переписку не
  попадает**, обратно ты его не показываешь.

## Шаг 0. Активация — ПЕРВЫЙ вопрос мастера

До проверки окружения и этапов спроси **ключ активации** — он выдан клиенту при покупке.
Сначала проверь, не активировано ли уже (идемпотентность, повтор безопасен):

```bash
PY installer/activation.py --json
```

Если в выводе есть непустой `code`/`status` — активация уже пройдена: коротко скажи
«Доступ уже активирован» и переходи к Шагу 0.1, **не** переспрашивая ключ.

Иначе — через `AskUserQuestion` попроси ключ: «Введите ключ активации, который вам выдали
при покупке. Он выглядит так: **KZ-XXXXX-XXXXX-XXXXX-XXXXX**». Предупреди, что ключ
сохранится скрыто и в переписке показан не будет. Затем проверь и запиши его:

```bash
PY installer/activation.py --check "<КЛЮЧ КЛИЕНТА>"
```

- **Код возврата 0** — ключ принят: скажи «Ключ принят, продолжаем» (сам ключ **не
  повторяй**) и иди на Шаг 0.1.
- **Код возврата 1** — скрипт печатает по-русски, что не так (не тот формат / опечатка в
  контрольной части). Переведи это клиенту мягко и попроси ввести ключ ещё раз (до 2–3
  попыток). Без ключа установку не начинай — объясни, что он нужен для доступа.

Это **локальная** проверка формата ключа (офлайн-дружелюбно); привязка к серверу
лицензий появится позже — сейчас корректного по формату ключа достаточно. Значение ключа
в чат никогда не выводи.

## Шаг 0.1. Рабочая папка, интерпретатор, статус этапов

Определи корень (текущая папка проекта), проверь, что рядом есть `install/`. Выбери
Python по правилу из шапки — **на обеих ОС одинаково: имя не угадываешь, а берёшь
`python.recommended.path` из `PY_BOOT install/check_env.py --json`**; различается
только то, чем взять `PY_BOOT` (Windows — питон из папки завода, macOS — любой
`python3`). Это `PY`.

Покажи клиенту, где он находится по этапам:

```bash
PY install/stages.py --status
```

Также возьми машинную версию для себя (какие этапы есть, что пройдено, что дальше):

```bash
PY install/stages.py --json
```

## Шаг 1. Определи, какой этап ставить

- Клиент написал **«установи этап N»** (или «этап 2», «третий этап») → цель — этап `N`.
- Клиент написал просто **«установи» / «продолжи» / «следующий этап»** → цель — поле
  `next` из `--json` (первый непройденный этап). Если `next` пуст — всё уже стоит,
  поздравь и предложи пользоваться заводом.

Определи номер этапа надёжно (не угадывай на глаз):

```bash
PY install/stages.py --resolve "<фраза клиента, напр. 'этап 2' или 'next'>"
```

Скрипт печатает номер этапа. Дальше обозначаю его как `N`.

**Контроль порядка (мягко).** Этапы последовательны. Если клиент просит этап 2 или 3,
а более ранний ещё не пройден (`installed:false` в `--json`), не ставь через голову:
объясни по-человечески, что сначала нужен предыдущий этап (он — фундамент), и предложи
начать с него. Согласится идти по порядку — ставь предыдущий.

**Впервые запускают установку?** Коротко расскажи весь маршрут в 3 этапа (из `intro`
каждого этапа в `--json`), потом ставь этап 1.

## Шаг 2. Проверка окружения (здесь же определяется ОС)

```bash
PY install/check_env.py
```

Первая строка вывода — какая это ОС; дальше по каждому пункту «✓ / ✗ / •» и **готовая
команда-починка именно для этой ОС**. Машинный вид — `--json` (поле `os`: `windows`,
`macos` или `linux`). Никуда не ходит по сети и ничего не ставит: только смотрит.

Прочитай вывод. Если код возврата 1 (нет подходящего Python) — переведи проблему
клиенту простыми словами и назови команду, которую скрипт уже подобрал под его ОС.
**Системный ffmpeg не обязателен** — движок берёт его из пакета `imageio-ffmpeg`;
его отсутствие не преграда, продолжай.

**git у клиента НЕ нужен и НЕ является нехваткой.** Обновления завод получает сам
по защищённой ссылке, git в этом не участвует; материалы приходят через Google Диск.
На чистой Windows git не стоит никогда — это норма. Скрипт помечает его
`git.required: false` и не роняет код возврата. **Не предлагай клиенту ставить git**
и не описывай его отсутствие как проблему (`git.required: true` бывает только на
машине разработки, где рядом лежит репозиторий).

**Код возврата 1, но `python.switch_interpreter: true` — это НЕ «нехватка».** Значит
подходящий питон уже есть, просто проверка запущена не тем. Ставить клиенту нечего:
возьми `python.recommended.path` как `PY`, повтори `PY install/check_env.py` и иди
дальше. Клиенту про это не рассказывай — это внутренняя кухня, а не его проблема.
Типовой случай **обеих** ОС: на маке `python3` — это системный 3.9, на Windows нужный
питон лежит внутри папки завода (`recommended.in_box: true`) и не в PATH.

Если чего-то системного не хватает и клиент просит — можешь поставить за него (это
установка ПО, не публикация). Спроси разрешение: «Поставить X? Это бесплатно и нужно
для работы». Ставится это так:

- **Windows:** `winget install ...` — встроен в Windows 10/11, ничего доустанавливать
  не нужно.
- **macOS:** через **Homebrew** (`brew install ...`). Если `check_env.py` написал, что
  Homebrew нет — сам его молча не ставь: это установка стороннего менеджера пакетов
  в систему клиента. Объясни, что это «магазин программ для мака», дай ссылку `brew.sh`,
  попроси выполнить одну команду оттуда, потом повтори проверку. Альтернатива без
  Homebrew: свежий Python с `python.org` — больше для установки ничего не нужно.

  **Два подводных камня мака (иначе встанешь на ровном месте):**
  - установщик Homebrew на Apple Silicon в конце просит **дописать строку с
    `brew shellenv` в `~/.zprofile`** — это отдельное действие, без него `brew` не
    находится. Попроси клиента сделать и его тоже;
  - **перезапуск Терминала не помогает тебе**: PATH уже запущенной сессии от этого
    не меняется. Поэтому brew зови **полным путём** — он приходит в
    `check_env.py --json`, поле `pkg_manager.path` (там же `git.path`, `ffmpeg.path`
    и `binaries[].path`). Если `pkg_manager.ok: false`, а клиент говорит, что brew
    поставил — попроси его **перезапустить Claude Code**: новая сессия подхватит PATH.

**Что на macOS иначе (скажи клиенту, если он на маке):**

- если коробку скачали архивом, macOS может держать её «в карантине» — тогда один раз
  `xattr -dr com.apple.quarantine <папка завода>`;
- папка Google Диска лежит не «в компьютере», а обычно в
  `~/Library/CloudStorage/GoogleDrive-<почта>/Мой диск` — мастер сам найдёт её и
  предложит выбором на Шаге 5;
- GPU нет ни на Windows-машинах клиентов, ни на маке — движок и так рассчитан на
  процессор, ничего дополнительно включать не надо.

Проверку окружения делай на каждом этапе — она быстрая и идемпотентная.

## Шаг 3. Собери потребности этапа `N`

```bash
PY install/collect_manifests.py --stage N --json > install/.plan.json
PY install/collect_manifests.py --stage N          # русская сводка — покажи кратко
```

- Если сводка содержит блок «ПРОБЛЕМЫ» и код возврата 2 — это **конфликт версий pip**
  или незапиненная версия. Это дефект коробки, не вина клиента: остановись, попроси
  сообщить разработчику (Антону), процитировав проблему. Дальше не ставь.
- Если в плане **0 модулей** (у этого этапа в этой коробке пока нет инструментов —
  бывает до слияния сборки): честно скажи, что инструменты этого этапа в коробку пока
  не вошли, и **не** отмечай этап пройденным. Иначе продолжай — план в `install/.plan.json`.

## Шаг 4. Поставь зависимости этапа в локальный .venv

```bash
PY install/make_venv.py --plan install/.plan.json
```

Создаёт/дополняет `.venv` внутри папки завода (систему клиента не трогаем) и ставит
пакеты этапа одним заходом. Может идти долго (тяжёлые пакеты вроде torch/mediapipe на
этапе 1). Ошибка — чаще всего интернет или сборка тяжёлого колеса: предложи проверить
интернет и повторить — уже поставленное не переустановится.

## Шаг 5а. Селектор соцсетей (только когда у этапа есть сети)

Некоторые этапы подключают публикацию в соцсети (этап 2 — лента/Reels: модуль
`publishing`; этап 3 — сторис: модуль `story-publisher`). Если в `install/.plan.json`
среди `config_questions` есть ключи публикации (любой из `upload_post_api_key`,
`upload_post_user`, `vk_app_id`, `vk_user_token`, `vk_group_id`, `tg_bot_token`,
`tg_chat_id`, `vk_stories_token`) — **сначала спроси клиента, какие сети он хочет
подключить, и дальше спрашивай ключи ТОЛЬКО для выбранных сетей.** Если сетевых ключей
в плане нет (этап 1) — этот шаг пропусти целиком, иди на Шаг 5.

1. Покажи каталог сетей с честными пометками зрелости (ничего не пишет):

   ```bash
   PY install/networks.py --list
   ```

   Пометки честные и их надо озвучивать как есть: **«проверено боем»** (Instagram,
   YouTube, Threads, Telegram, ВКонтакте) и **«есть, но не обкатано — на свой риск»**
   (LinkedIn, Facebook, X, TikTok, Reddit, Bluesky, Discord, Google Business, Pinterest).
   Не выдавай «на свой риск» за готовое: так и говори — «код есть, живьём не гоняли,
   подключаем под вашу ответственность».

2. Через `AskUserQuestion` дай **мультивыбор** сетей (каждая сеть — отдельная опция,
   в подписи — имя сети и пометка зрелости, напр. «Instagram — проверено боем»,
   «TikTok — на свой риск»). Разрешено выбрать несколько. Машинные `id` сетей возьми
   из `--list` (поле `id`) или из `install/networks.py --json`.

3. По выбранным `id` получи список ключей, которые реально нужны (ничего не пишет):

   ```bash
   PY install/networks.py --keys "<id через запятую, напр. instagram,vkontakte>"
   ```

   Скрипт печатает канонические ключи (по одному в строке) — это объединение
   требований выбранных сетей. На Шаге 5 **задавай из `config_questions` только те
   вопросы, чей `key` попал в этот список** (плюс несетевые вопросы этапа, если есть).
   Вопросы ключей невыбранных сетей — не задавай вовсе: не выбрал TikTok — не спрашивай
   про него ничего. Пустой выбор (клиент не хочет пока ничего подключать) — законно:
   пропусти все сетевые вопросы, модули пойдут в урезанном режиме.

4. **Chrome-проводник подключения аккаунтов (мастер ведёт, но не входит за клиента).**
   Часть сетей подключается получением ключа/токена, часть — входом в кабинете
   Upload-Post. Способ у каждой сети виден в `--json` (поле `connect`). Если у клиента
   есть Claude-в-Chrome, для каждой выбранной сети ты можешь **провести его по шагам**:
   - `upload_post_cabinet` (Instagram, YouTube, Threads и все «на свой риск», Telegram-лента):
     открой `upload-post.com`, покажи, где кнопка подключения аккаунта площадки, доведи
     до OAuth площадки и до места, где в кабинете лежит ключ (`API keys`). Ключ клиент
     копирует и даёт тебе как ответ на вопрос `upload_post_api_key`, имя профиля — как
     `upload_post_user`.
   - `vk_oauth` (ВКонтакте): открой страницу входа VK ID, доведи до экрана «Разрешить»,
     поймай готовый ключ доступа (тебе поможет `vk_auth.py`). Записывается в `vk_user_token`.
   - `tg_bot` (Telegram-архив): проведи клиента по шагам у `@BotFather` (`/newbot`),
     он создаёт бота и копирует ключ (`tg_bot_token`), затем добавляет бота в свой
     канал администратором; адрес канала — `tg_chat_id`.

   **ЖЁСТКОЕ ПРАВИЛО БЕЗОПАСНОСТИ (границу не переступать ни на одной сети):**
   **система НЕ вводит пароль клиента, НЕ создаёт за него аккаунты и НЕ нажимает
   согласие OAuth за него.** На шаге ввода пароля, на кнопке «Разрешить»/«Allow» и на
   создании аккаунта ты **ставишь паузу и просишь клиента сделать это своими руками** —
   печатаешь только то, что он тебе продиктовал (имя профиля, номер группы), а пароли
   и согласия он вводит и нажимает сам. Чужие учётные данные ты не вводишь никогда.
   Ключ/токен, который клиент тебе продиктовал, ты записываешь в ответ на вопрос (Шаг 5),
   но в чат его не повторяешь.

## Шаг 5. Вопросы клиенту — ТОЛЬКО ВЫБОРОМ

Вопросы не придумывай и не задавай свободным текстом. Готовый список бери отсюда:

```bash
PY install/questions.py --plan install/.plan.json --json      # для тебя
PY install/questions.py --plan install/.plan.json --render    # как это выглядит человеку
```

Если был Шаг 5а (селектор соцсетей) — добавь `--only-keys "<ключи из networks.py --keys,
через запятую>"`, чтобы не спрашивать про невыбранные сети.
На **этапе 1** оставь собственные вопросы мастера по умолчанию (`gdrive_root`,
`brand_preset`). На **этапе 2** передай `--wizard "speech_recognition"` — это
вопрос про распознавание речи, без него веса не скачаются НИКОГДА (шаг раньше
лежал вне цепочки, отсюда `models=false` у всех клиентов). На **этапе 3**
передай `--wizard ""` — там всё уже отвечено.

Ответ «да» на этом вопросе означает загрузку около 2,7 ГБ: запусти её
`PY install/install_models.py --download` и предупреди, что это 10 минут–час
и один раз навсегда. Ответ записывай ДО загрузки — тогда обрыв связи читается
как «согласился, не встало», а не как отказ клиента.

Каждый вопрос приходит по контракту (`PY install/questions.py --schema`):

| поле | что с ним делать |
| --- | --- |
| `ask` | сам вопрос — задай его как есть |
| `why` | зачем спрашиваем — скажи одной фразой перед вариантами |
| `options[]` | **варианты для `AskUserQuestion`**: `label` — подпись опции, `consequence` — описание опции («что будет, если выбрать») |
| `default: true` | пометь как «по умолчанию» и поставь первым |
| `recommended: true` | можно добавить «советую» |
| `free_text: true` | выбор этого варианта = задать **второй**, уже свободный вопрос («введите ключ / путь / слово») |
| `later: true` | «Не знаю / решу позже» — в `install/.answers.json` ключ **не пиши вовсе**, а запомни его как отложенный (см. Шаг 6, `--deferred`), чтобы вопрос всплыл при следующей установке |
| `previous` | клиент уже отвечал так в прошлый раз: скажи «в прошлый раз вы выбрали …, оставляем?» |
| `already_set` | секрет уже сохранён — не переспрашивай, только предложи поменять |
| `secret: true` | предупреди, что значение сохранится скрыто; **введённое не повторяй** |
| `input: multi_choice` | можно выбрать несколько; значения склей строкой через поле `join` |

Жёсткие правила:

- **Никаких вопросов «впишите значение» без предварительного выбора.** Свободный ввод
  допустим только после варианта с `free_text` — то есть для ключей доступа, ссылок,
  путей и своего числа.
- Записывай **машинное значение** (`value`), а не русскую подпись. Вариант с
  `value: null` (пропуск / «решу позже») — ключ в ответы **не** записывай вовсе,
  модуль возьмёт свой дефолт.
- Не выдумывай варианты, которых нет в выводе. Установщик перепроверит: значение не
  из списка он не запишет.
- Одинаковый ключ у разных модулей уже объединён — дважды не спрашивай.

**Оформление (вопрос `brand_preset`).** Список пресетов читается из папки `styles/`
динамически — что там лежит, то и предлагается (`PY install/questions.py --styles`).
Объясни просто: это шрифт, вид подписей под видео и отступы от краёв; поменять можно
в любой момент, ничего не сломается. Выбор запоминается и подставляется движку
(`factory_config.style_file()`).

🖼 **Сначала покажи витрину, потом спрашивай.** Названия пресетов человеку ничего
не говорят — по «brand-minimal-light» невозможно понять, как это выглядит. Открой
клиенту `styles/preview/BRAND_CATALOG.jpg` (лист со всеми фирменными стилями, едет
в коробке вместе с папкой `styles/`) и только после этого предложи список. Стили
каруселей — отдельная витрина `ученикам/BANK_SHABLONOV.jpg` + описания в
`ученикам/05a_БАНК_ШАБЛОНОВ.md`; её показывают перед первой каруселью, правило
записано в клиентском `CLAUDE.md`. Файла витрины на месте нет — не выдумывай, как
выглядят стили: скажи прямо и предложи собрать пример.

Собери ответы в `install/.answers.json` — плоский JSON `{"ключ":"значение", ...}`.
Пиши через Bash/heredoc, **не** показывая секреты в тексте. Если вопросов у этапа нет —
файл можно не создавать, шаг 6 всё равно создаст папки.

## Шаг 6. Запиши конфиг и создай папки этапа

```bash
PY install/setup_config.py --answers install/.answers.json --plan install/.plan.json
```

(Если `install/.answers.json` не создавался — передай пустой `{}` через временный файл,
чтобы скрипт всё равно создал маркер корня и папки этапа.)

Скрипт разложит несекретное в `config/factory.config.json`, секреты — в `.env` (скрыто,
права 0600), создаст маркер корня и папки модулей этапа.

Структуру на Google Диске (этап 1, когда задан `gdrive_root`) создаёт **единый
контракт** `modules/intake/drive_structure.json` — имена папок нигде не дублируются:

```bash
PYTHONPATH=modules PY -m intake.drive_layout --root "<gdrive_root>" --client "<имя клиента>"
```

**`PYTHONPATH=modules` обязателен** во всех вызовах `PY -m intake.…`: модули лежат
в `modules/<имя>/`, и без этого будет `ModuleNotFoundError: No module named 'intake'`
(так же делает `install/run_doctors.py`). Значение из одного каталога — работает
одинаково на маке и на Windows, разделитель путей не нужен.

Повторный запуск безопасен: существующие папки и подсказки не трогаются.

**Только на macOS — подключи медиа-папки ссылками.** Делает это `link_media_mac.sh`
(лежит в коробке). На Windows этого шага нет — там медиа-путь работает как есть,
и никакого скрипта в коробке для него не лежит. Запускай его
**только если `check_env.py` сказал `os: macos`**:

```bash
bash link_media_mac.sh
```

Скрипт сам ищет общую медиа-папку на смонтированном Google Диске и заменяет пустые
папки-приёмники симлинками; повтор безопасен. **Код возврата 1 — это НЕ поломка
установки:** значит общей медиа-папки на Диске нет (у большинства клиентов её и не
будет). Скажи об этом одной фразой («медиа-папки подключать нечего — работаем с
тем, что кладёте в „1 Сырьё“») и продолжай этап. Путь можно передать явно:
`bash link_media_mac.sh "<путь к медиа-папке>"`.

#### Шаг 6б. Быстрая загрузка фото — два клика клиента (обе ОС)

**Зачем.** Фото и видео лежат в облаке, и завод скачивает каждый кадр заново в
момент сборки. ЗАМЕР 07.08.2026: на узком канале это ~5 секунд на кадр, то есть
почти минута ожидания на одну карусель. Если папка помечена «доступ офлайн»,
Диск держит её на компьютере и сборка перестаёт ждать вовсе.

Сделать это может **только клиент руками** — настройка живёт в самом Google
Диске, из завода её не переключить. Поэтому проведи клиента за руку: он
отвечает «да» и делает два клика, инструкции не изучает.

**Сначала проверь, влезет ли.** Папка скачается на компьютер целиком:

```bash
PY -c "import os,shutil,sys; d=sys.argv[1]; t=sum(os.path.getsize(os.path.join(d,f)) for f in os.listdir(d) if os.path.isfile(os.path.join(d,f))); print(f'папка {t/1e9:.2f} ГБ, свободно {shutil.disk_usage(os.path.expanduser(\"~\")).free/1e9:.2f} ГБ')" "<путь к папке с медиа>"
```

- Свободного места **меньше, чем папка + 5 ГБ** — шаг пропусти и не предлагай:
  забить клиенту диск хуже, чем ждать лишнюю минуту на сборке. Скажи одной
  фразой, что ускорение отложили до освобождения места.
- Файлы и так лежат на компьютере (у клиента Диск в режиме зеркалирования) —
  скажи «у вас уже быстро» и иди дальше, ничего не предлагая.

**Спроси ОДИН раз, выбором:** «Включим быструю загрузку фото? Сборка перестанет
ждать облако, займёт у вас два клика, на компьютер скачается <N> ГБ.»
Отказ — нормальный ответ, завод работает полностью; **второй раз не предлагай**.

Сказал «да» — продиктуй клики своими словами, без слова «настройка»:

- **Windows:** открыть проводник → найти папку с фото на Google Диске →
  правый клик по ней → пункт **Google Drive** → **«Доступ офлайн»**.
- **macOS:** открыть Finder → правый клик по папке с фото →
  пункт **Google Drive** → **«Доступ офлайн»**.

Дальше Диск скачивает папку в фоне сам — минуты или десятки минут, зависит от
интернета. Работать можно сразу, ждать не нужно: сборки будут ускоряться по
мере скачивания. Галочку клиент ставит один раз навсегда.

⚠️ Не путай это с прогревом внутри завода: прогрев подтягивает кадры перед
сборкой, но Диск вправе вычистить их из кэша, когда ему нужно место.
Помеченное «офлайн» он не вычищает никогда — только поэтому шаг и существует.

#### Шаг 6.0. Если клиент подключил Google Диск К КЛОДУ (коннектор) — наведи порядок САМ

Многие клиенты подключают свой Google Диск не как локальную папку, а **напрямую к
Клоду** (коннектор Google Drive). Как только диск подключён к тебе — **не жди
локальной синхронизации, зайди на диск сам и наведи порядок** по контракту:

1. Прочитай контракт структуры — **единственный источник правды**:
   ```bash
   PYTHONPATH=modules PY -m intake.drive_layout --connector-plan   # JSON: список папок + текст README
   ```
2. Через инструменты Google Drive коннектора создай в корне диска папку
   **«КонтентЗавод»** и внутри — всю структуру папок из плана (`1 Сырьё`,
   `2 На утверждение/Одобрено`, … `5 Смыслы и настройки`, `НЕ_ТРОГАТЬ` и подпапки).
3. В каждую папку положи её файл-подсказку **«ЧТО СЮДА КЛАСТЬ.txt»** (текст — из
   плана, поле `readme`), а в корень — **«КАК ЭТО РАБОТАЕТ.txt»** (поле `root_readme`).
4. **Идемпотентно:** сначала проверь, есть ли папка/файл (поиск по коннектору) —
   существующее НЕ дублируй и НЕ перезаписывай, создавай только недостающее.
5. Отчитайся клиенту простыми словами: «навёл порядок на твоём Google Диске —
   создал папки, в каждой лежит подсказка, что туда класть».

Это и есть «Клод сам зашёл на диск и разложил всё по структуре». Локальный путь
(`drive_layout --root`) и путь через коннектор дают ОДНУ И ТУ ЖЕ структуру из
одного контракта — используй тот, что подключил клиент.

### Шаг 6.1. Объясни клиенту, как устроен его диск

Папки уже созданы, доктор ещё не бежал — самое место рассказать человеку, куда
класть съёмку и где забирать готовое. Выведи текст **как есть**, ничего не спрашивая:

```bash
PYTHONPATH=modules PY -m intake.wizard_text
```

Клиенту важны три вещи, и они в тексте: снимаешь → кладёшь в «1 Сырьё»; завод
складывает готовое в «2 На утверждение»; **пока не перетащишь в «Одобрено» — никуда
не публикуется**. Это и есть предохранитель проекта, выраженный папками.

### Шаг 6.2. Файл смыслов — СКАЖИ клиенту, КОГДА и КУДА его грузить

**У каждого клиента файл со смыслами (Content Bible) появляется СРАЗУ ПОСЛЕ живого
Zoom-созвона с Валерией** — на созвоне она распаковывает смыслы и отдаёт готовый
файл. Обязательно скажи клиенту прямо на установке, простыми словами:

- «Сам файл со смыслами ты получишь **на созвоне с Валерией** — она его тебе отдаст.»
- «**Как только созвон закончится** и файл у тебя на руках — загрузи его в папку
  **«5 Смыслы и настройки»** на Google Диске **(или просто дай его мне — я положу
  куда надо и подключу к заводу)**.»
- «Это делается **сразу после созвона и ДО первых каруселей** — из этого файла
  завод пишет вообще все тексты. Без него контент будет пустым.»

Когда клиент даёт файл — положи его в «5 Смыслы и настройки» (локально в
`<gdrive_root>/КонтентЗавод/5 Смыслы и настройки/` или через коннектор Google
Drive, если диск подключён к тебе — см. Шаг 6.0) и подтверди, что завод его видит.
Если созвона ещё НЕ было — не блокируй установку: скажи, что файл появится после
созвона, и напомни загрузить его тогда.

Затем **запомни ответы**, чтобы при повторной установке не спрашивать всё заново
(секреты в память не попадают — их фильтрует сам скрипт):

```bash
PY install/questions.py --plan install/.plan.json --remember install/.answers.json \
   --deferred "<ключи, которые клиент отложил, через запятую>"
```

(`--deferred` можно опустить, если клиент ничего не откладывал.)

И только после этого удали временный файл ответов — в нём секреты:

```bash
rm -f install/.answers.json
```

Тяжёлые модели (лица/речь) на этом шаге **не** качаются — движок скачает их сам при
первом запуске. Клиенту так и скажи.

## Шаг 7. Проверка «всё ли живо» на этапе `N`

```bash
PY install/run_doctors.py --stage N
```

Прогонит `doctor` каждого модуля этапа и соберёт русскую сводку. Перескажи клиенту
простыми словами: что работает полностью, что в урезанном режиме и почему (каких ключей
не хватило и что из-за этого недоступно).

**На этапе 2 добавь отдельно:**

```bash
PY install/install_models.py --doctor
```

Он отличает «клиент отказался» от «должно было встать и не встало» — обычные
доктора этой разницы не видят и ругаются на отказавшегося клиента как на
поломку. Код 0 — всё в порядке, включая осознанный отказ; код 2 — не доделано
не по вине клиента, скажи об этом и предложи докачать одним шагом.

## Шаг 8. Отметь этап пройденным и подведи итог

```bash
PY install/stages.py --mark-done N
```

Затем дружелюбно закрой этап (данные бери из `--json`, поле этапа `N`):
- **ФУНДАМЕНТ — только на этапе 1.** Если у этапа есть поле `first_step` (оно есть у
  этапа 1) — озвучь его **в первую очередь и с нажимом**: первый шаг работы — это
  **распаковка смыслов**, её делают ДО каруселей. Карусели и Reels строятся на смыслах,
  а не наоборот. Предложи клиенту два пути: (а) живая сессия с Валерией — скилл
  `/self_unpacking` (Валерия ведёт голосом, это созвон, а не самоустановка); (б)
  самостоятельно — открыть файл `ученикам/02_РАСПАКОВКА_ВОПРОСЫ.md` (он лежит в папке
  завода) и сказать тебе «проведи со мной распаковку по этим вопросам». Не давай
  клиенту кидаться в карусели, пока смыслы не распакованы — мягко верни к фундаменту.
  **Файла на месте нет** (старая коробка, до которой не доехало обновление) — не
  показывай клиенту «файл не найден»: просто скажи «сейчас проведу распаковку сам»
  и задай вопросы по блокам сам, по одному, уточняя до конкретики.
- **что теперь работает** — поле `unlocks`;
- **что дальше** — поле `next_hint` (если этап не последний): «Когда будете готовы,
  напишите “установи этап N+1”».
- **предупреждения этапа** — поле `warnings`. На **этапе 3** обязательно предупреди:
  виральная разведка `/niche-hooks` — **ручной** инструмент и **тратит платные кредиты
  vidIQ**; запускается только по команде клиента, перед дорогим сбором сама показывает
  остаток и смету и ждёт «да». **Кредиты — с личного аккаунта vidIQ клиента** (отдельная
  платная регистрация, наши ключи в коробку не входят) — это скрытая стоимость, скажи о
  ней честно. Для разбора YouTube/TikTok нужны `yt-dlp` и `ffmpeg` (разведка Instagram
  работает и без них) — если `doctor` этого модуля сказал, чего не хватает, переведи клиенту.

Не запускай следующий этап сам — дождись, пока клиент попросит. Один прогон `/install`
= один этап.

## Шаг 8.1. Согласие на техническую сводку — один раз, спокойно

Завод может раз в сутки отправлять разработчику короткую **обезличенную**
техническую сводку (версия, пройденные этапы, что из проверок не сработало).
**Без согласия клиента не отправляется ничего** — это закон проекта и требование
152-ФЗ, а не настройка.

Сначала спроси скрипт, надо ли вообще спрашивать:

```bash
PY health_report.py --consent-state
```

`need_ask: false` → **молча пропусти этот шаг** (уже спрашивали, уже согласились
или клиент отказался). `need_ask: true` → задай ОДИН вопрос через AskUserQuestion:

- перескажи своими словами суть: раз в сутки уходит короткая техническая сводка —
  версия программы, какие этапы установки прошли, что из проверок не сработало;
- скажи прямо, чего там **нет**: имени, почты, текстов, смыслов, фото, видео,
  ключей, паролей, путей на компьютере;
- скажи, что можно посмотреть полный текст (`PY health_report.py --consent-text`)
  и саму сводку целиком (`--show`);
- скажи, что отказ **ни на что не влияет** и что согласие можно отозвать в любой
  момент словами «выключи сводку о здоровье».

Варианты ответа — ровно два, оба спокойные: «Да, можно» и «Нет, не надо».
Сразу после вопроса отметь, что он задан:

```bash
PY health_report.py --consent-asked
```

Дальше по ответу:

```bash
PY health_report.py --consent-grant --how installer    # клиент сказал «да»
PY health_report.py --consent-deny  --how installer    # клиент сказал «нет»
```

**Отказ — нормальный рабочий сценарий.** Не уговаривай, не объясняй выгоду
второй раз, не возвращайся к теме ни в этом прогоне, ни в следующих этапах.
Клиент промолчал / ушёл от ответа — считай это «нет на сегодня»: ничего не
записывай кроме `--consent-asked` и иди дальше.

## Повторная установка того же этапа

Повтор безопасен и ожидаем (клиент дозавёл ключ, поменял стиль, передумал про частоту).
Перед вопросами посмотри, что уже отвечено:

```bash
PY install/questions.py --previous
```

Прошлые ответы приходят в вопросах полем `previous` и уже стоят вариантом по умолчанию:
спрашивай «в прошлый раз вы выбрали …, оставляем?» — и не заставляй проходить всё заново.
Отложенные («не знаю / решу позже») помечены и задаются снова. Уже сохранённые ключи
(`already_set`) не переспрашивай.

## Если что-то пошло не так

- Любую техническую ошибку переводи в понятную фразу + одно действие.
- Ничего у клиента без спроса не удаляй. Повтор этапа безопасен и идемпотентен.
- Конфликты версий/пиннинга/AGPL и «0 модулей у этапа» — это дефект коробки: адресуй
  разработчику, не клиенту.
- На macOS ошибка вида «нет прав» / «файл повреждён» после распаковки архива — это чаще
  всего карантин: `xattr -dr com.apple.quarantine <папка завода>` один раз.
